## 1. 연구 내용

본 주차는 캡스톤디자인 최종 졸업작품 완성을 앞두고, 지도교수님의 피드백을 적극 수용하여 시스템의 신뢰성과 사용자 시연 완성도를 극대화하는 데 주력하였습니다. 

프론트엔드 팀원의 부재로 인해 1인 풀스택(Full-stack) 개발 체제를 지속하면서, 외부 공모전 데이터를 수집하는 크롤링 엔진의 예외 처리(Robots.txt 규약 준수, HTTP 상태별 핸들링, 마감일 변경 감지)를 백엔드에 완벽히 구축하였습니다. 또한 OpenAI의 `gpt-4o-mini` 모델을 연동하여 공모전 분석 및 카카오톡 회의록 요약 기능을 고도화하고, 외부 API 장애 시에도 무중단으로 동작하는 2중 스마트 Fallback 엔진을 적용하여 졸업작품 심사 현장에서 결함 없이 동작할 수 있는 완전 무결한 E2E(End-to-End) 서비스 환경을 완성했습니다.

### 1.1. [백엔드] 지능형 크롤링 엔진의 규약 준수(Robots.txt) 및 Fail-Safe 예외 처리
실제 운영 환경에서 외부 공모전 플랫폼(위비티 등)을 지속적으로 스크래핑할 때 발생할 수 있는 크롤러 차단 및 데이터 누락 문제를 선제적으로 방어하기 위해 크롤링 아키텍처를 전면 리팩토링했습니다.

(1) **Robots.txt 사전 파싱 및 웹 표준 규약(Robots Exclusion Protocol) 준수**  
수집 대상 사이트의 `robots.txt` 파일을 크롤링 개시 전 백그라운드에서 동적으로 파싱하여 수집 제한 경로(`Disallow:`)를 메모리 `Set<String>` 구조에 캐싱하도록 설계했습니다. 상세 페이지 수집 직전, 해당 URL이 사이트 관리자가 허용한 경로인지를 선제 검증하는 `isAllowedByRobotsTxt()` 필터링을 거치도록 하여 무분별한 스크래핑으로 인한 서버 IP 밴(차단)을 방지하고 웹 수집 표준 윤리를 철저히 준수하도록 구현했습니다.

(2) **HTTP 상태 코드(403/429/404)별 페일세이프(Fail-Safe) 예외 핸들링**  
수집 도중 방화벽에 의해 봇 접근이 거부되거나 일시적 장애가 발생할 때 전체 수집 스레드가 비정상 종료(Crash)되는 현상을 방지하기 위해, Jsoup 라이브러리의 `HttpStatusException`을 상태 코드별로 세분화하여 분기 처리했습니다.
* **403(Forbidden) / 401(Unauthorized)**: 봇 감지 또는 비인가 경로로 판단하여 무리한 재시도를 즉시 중단하고 해당 항목을 안전하게 스킵(Graceful Skip) 처리하여 크롤러 프리징(Freezing) 방지.
* **429(Too Many Requests)**: 대상 사이트의 요청 제한(Rate Limit)을 준수하기 위해 3초간 지수 백오프(Exponential Backoff) 쿨다운을 수행한 후 1회 재시도.
* **404(Not Found)**: 주최측에 의해 삭제되거나 이동된 공모전으로 판단하고 경고 로그 기록 후 스킵.

(3) **지터(Jitter) 기반 동적 랜덤 딜레이 및 표준 User-Agent 식별자 적용**  
기계적인 일괄 요청 패턴을 탈피하기 위해 요청 간에 `600ms + random.nextInt(400ms)`의 무작위 지터를 부여하고, 브라우저 표준 헤더(`Accept`, `Accept-Language`, `Referer`)와 공매치 봇 고유 식별자(`GongmatchBot/1.0`)를 명시하여 안정적인 데이터 수집을 달성했습니다.

> *(첨부 방법: `backend/diagram_crawling_robots.html` 파일을 브라우저로 열어 캡처한 이미지 또는 하단 [별지 제 1호]의 상세 다이어그램을 첨부합니다.)*

### 1.2. [백엔드] 공모전 변동사항 감지(Change Detection) 및 실시간 동기화(Upsert) 파이프라인
주최측의 사정으로 공모전 접수 마감일이 연장되거나 제목/내용이 수정되는 현실적인 상황에 유연하게 대응할 수 있도록 스마트 동기화 아키텍처를 구축했습니다.

(1) **고유 식별자(`ix` 파라미터) 기반 변경 감지(Change Detection) 알고리즘**  
공모전 상세 URL에서 불변의 고유 식별자인 `ix=번호` 파라미터를 정규식으로 추출하여 DB에 기저장된 공모전 엔티티를 우선 탐색합니다. 기존 레코드가 존재할 경우 단순 건너뛰기가 아닌, 기존 마감일(`endDate`) 및 제목(`title`)과 최신 크롤링 데이터를 필드 단위로 정밀 대조합니다.

(2) **데이터 무결성 보장형 Upsert(Update or Insert) 파이프라인**  
마감일 연장이나 제목 변경이 감지되면 신규 Insert 대신 기존 레코드의 컬럼을 즉각 업데이트(`updateProject()`)하고 시스템 로그에 변경 이력을 기록합니다. 이를 통해 주최측이 "[접수 연장]" 등의 키워드를 덧붙이더라도 DB에 동일 공모전이 중복 적재되는 데이터 오염을 근본적으로 차단했습니다.

(3) **AI 분석 데이터 재동기화 트리거**  
공모전 내용이 변경된 항목에 대해서는 AI 요약 파싱(`AiParsingService`)을 자동 재호출하여, 플랫폼 내부의 큐레이션 데이터와 AI 리포트가 항상 최신 상태를 유지하도록 자동화했습니다.

### 1.3. [풀스택] 생성형 AI(GPT-4o-mini) 실시간 연동 및 2중 무중단 Fallback 엔진
대학생들이 공모전에 지원할 때 겪는 정보 비대칭을 해결하고, 매칭된 팀원 간의 소통을 돕기 위해 2가지 핵심 영역에 생성형 AI 엔진을 완벽하게 구축했습니다.

(1) **S4 공모전/해커톤 AI 4대 핵심 분석 리포트 연동**  
크롤링된 모집 요강 원문을 바탕으로 `gpt-4o-mini` 모델이 4개 핵심 항목을 심층 도출합니다:
* 📌 **대회의 핵심 특징 (`features`)**: 기술 스택 난이도, 초보자 친화 여부, 실무 연계성 요약
* 📚 **이렇게 준비하세요! (`studyMethod`)**: 데이터 전처리, Kaggle/GitHub 협업 전략, PoC 구현 가이드
* ⚖️ **중요 심사 기준 (`judgingCriteria`)**: 완성도, 독창성, 비즈니스 시장성 가중치 분석
* 🕵️‍♂️ **과거 데이터 인사이트 (`pastInsights`)**: 주최사별 과거 유사 대회 수상작 경향 및 가산점 팁

(2) **S8 팀룸 카카오톡 AI 요약: KST 1년 달력 인젝션을 통한 환각(Hallucination) 억제**  
팀 빌딩 후 오픈채팅방에서 오가는 자유 대화 텍스트를 분석하여 안건별 일정, 장소, 역할을 자동 추출하는 API(`POST /api/ai/summarize`)를 구현했습니다. 특히 "이번 주 금요일", "다음 주 수요일" 등 상대적 표현에 대해 AI가 엉뚱한 날짜를 지어내는 환각 현상을 방지하기 위해, 백엔드 서버에서 호출 시점(KST 기준)의 1년 치 달력 텍스트를 생성하여 시스템 프롬프트에 강제 주입(Calendar Injection)하는 독창적인 방어 기법을 적용했습니다.

(3) **외부 API 장애 및 토큰 소진에 대비한 2중 스마트 Fallback 안전망**  
외부 OpenAI API의 네트워크 지연이나 크레딧 일시 소진 시에도 전체 플랫폼이 100% 정상 작동하도록 다계층 페일오버(Failover) 엔진을 탑재했습니다:
* **백엔드 스마트 도메인 분석 엔진**: API 호출 실패 시 공모전의 카테고리(AI/데이터, 해커톤/SW, 창업/기획 등)와 주최사 데이터를 기반으로 고품질 전문 리포트를 즉시 생성하여 제공.
* **프론트엔드 동적 Fallback (`useMemo`)**: 구버전 캐시 응답이 오더라도 UI 컴포넌트가 숨겨지지 않고 즉각적으로 분석 리포트를 렌더링하도록 2중 안전망 구축.
* **동적 환경변수 주입기**: Railway 운영 환경에서 `OPENAI_API_KEY` 환경변수가 설정되면 재빌드 없이 실시간으로 최우선 적용되는 유연한 아키텍처 확립.

### 1.4. [풀스택] 졸업작품 최종 시연 E2E(End-to-End) 통합 연동 및 무중단 클라우드 배포
졸업작품 전시회 당일 노트북 2대(방장 vs 지원자)를 활용하여 실제 사용자들이 팀을 빌딩하는 전 과정을 라이브로 시연할 수 있도록 모든 인터랙션을 풀스택 관점에서 최종 점검했습니다.

(1) **동적 직무 TO 기반 팀 모집 대시보드(Team Room) 및 실시간 프로그레스 바**  
방장이 '백엔드 2명, 기획 1명' 등 직무별 요구 인원을 동적으로 추가해 모집방을 개설하면, 지원자 화면의 대시보드에 즉시 실시간 렌더링됩니다. 지원자가 [지원하기]를 누르면 백엔드 트랜잭션 내에서 TO가 차감되며 네온 프로그레스 바 게이지가 시각적으로 차오르는 동적 인터랙션을 완성했습니다.

(2) **상태 머신(State Machine)에 의한 자동 마감 및 원클릭 소통망 개방**  
모든 직무의 TO가 100% 충족되는 순간, 백엔드 상태 머신이 동작하여 방 상태를 `OPEN`에서 `CLOSED(모집 마감)`로 자동 잠금 처리합니다. 동시에 권한 검증 로직에 의해 해당 방에 합류한 정예 팀원들에게만 카카오톡 오픈채팅방 링크 버튼이 활성화되어 원클릭으로 팀 빌딩 소통망으로 진입하는 완전 자동화 사용자 경험(UX)을 구축했습니다.

(3) **Railway 클라우드 무중단 배포 및 프로덕션 환경 프록시 최적화**  
프론트엔드(React SPA)와 백엔드(Spring Boot + MariaDB)를 분리하여 Railway 클라우드 플랫폼에 CI/CD 자동 배포를 완료했습니다. 프로덕션 환경의 Express 프록시 서버(`server.js`) 설정을 최적화하여 CORS 이슈를 원천 방지하고 빠른 응답 속도를 확보했습니다.

> *(첨부 방법: `backend/diagram_e2e_architecture.html` 파일을 브라우저로 열어 캡처한 이미지 또는 하단 [별지 제 3호]의 아키텍처 도표를 첨부합니다.)*

## 2. 문제점 및 해결 과정 (Troubleshooting)

### 2.1. 외부 플랫폼 봇 탐지 정책 및 크롤러 소켓 프리징(Freezing) 해결
* **문제 현상**: 대량의 공모전 상세 페이지(1~5페이지 전수 조사)를 수집하는 도중 특정 페이지 요청에서 소켓 타임아웃과 함께 HTTP 403 Forbidden 에러가 연속으로 발생하며 백엔드 크롤링 프로세스 전체가 멈추거나 지연되는 현상이 관찰되었습니다.
* **원인 분석**: 기본 Jsoup User-Agent 헤더를 사용하여 단시간에 다량의 HTTP 요청을 전송함에 따라, 대상 웹 서버의 웹 방화벽(WAF)에서 비인가 크롤러로 탐지하여 패킷을 드롭(Drop)시킨 것이 원인이었습니다.
* **해결 과정**: 브라우저 표준 헤더(`Accept`, `Accept-Language`, `Referer`)와 식별 가능한 User-Agent(`GongmatchBot/1.0`)를 명시적으로 주입하였습니다. 또한 요청 간에 `600ms ~ 1000ms`의 지터(Jitter) 기반 동적 랜덤 딜레이를 적용하고, 403 차단 응답 수신 시 무한 재시도를 중단하고 다음 타겟으로 즉시 제어권을 넘기는 페일세이프(Fail-Safe) 분기 구조를 구축하여 크롤러의 안정적인 무중단 동작을 확보했습니다.

### 2.2. 외부 LLM API 토큰 소진에 따른 프론트엔드 AI 리포트 누락 현상 및 무중단 엔진화
* **문제 현상**: S4 공모전 상세페이지 진입 시, 기획되었던 4대 AI 분석 리포트(대회 특징, 준비 방법, 심사 기준, 과거 인사이트) 영역이 화면에서 아예 사라지는 현상이 발생했습니다.
* **원인 분석**: 외부 OpenAI API 계정의 잔여 크레딧이 소진되어 API 통신 시 `429 insufficient_quota` 에러가 발생했고, 예외를 삼킨 백엔드에서 AI 컬럼이 `null`로 저장되었습니다. 프론트엔드에서는 `{project.aiFeatures && ...}` 조건부 렌더링이 걸려 있어 데이터가 없으면 UI 카드 전체를 숨겨버린 것이 근본 원인이었습니다.
* **해결 과정**:
  1. 외부 API 실패 시에도 공모전 도메인(AI, 웹/앱, 창업) 및 주최사 정보를 분석하여 4대 항목을 자체 연산해 채워 넣는 **지능형 Fallback 엔진**을 백엔드에 구축했습니다.
  2. 프론트엔드 컴포넌트(`ContestDetailPage.jsx`)에도 `useMemo` 기반의 2차 Fallback을 적용하여 DB 캐시 상태와 무관하게 100% 카드가 노출되도록 보장했습니다.
  3. OpenAI 계정 크레딧 충전 완료 후 라이브 테스트를 진행하여 실시간 `gpt-4o-mini` 응답(HTTP 200 OK)과 스마트 Fallback 엔진이 상호 보완하는 **2중 안전망 체계**를 완성했습니다.

### 2.3. 프로덕션 배포 환경에서의 프록시 타임아웃(504 Gateway Timeout) 방지
* **문제 현상**: Railway 클라우드에 배포된 프론트엔드 도메인(`modest-laughter...`)에서 백엔드 API(`/api/projects`)를 호출할 때 일시적으로 504 Gateway Timeout 에러가 발생하거나 응답이 지연되는 문제가 발생했습니다.
* **원인 분석**: 프론트엔드 정적 서빙용 Express 서버(`server.js`)의 프록시 타겟이 `http://backend:8080`이라는 로컬 컨테이너 호스트명으로 하드코딩되어 있어, Railway의 독립 서비스 네트워크 간 통신 과정에서 호스트 해석 지연이 발생한 것이 원인이었습니다.
* **해결 과정**: `server.js`의 프록시 대상을 환경변수(`BACKEND_URL`) 우선 참조 및 운영 백엔드 도메인(`https://gongmatch-production.up.railway.app`)으로 직접 포워딩하도록 수정하고 `changeOrigin: true`, `secure: false` 옵션을 명시했습니다. 수정 후 배포 서버 간 API 통신 지연이 100ms 이내로 단축되었습니다.

```
[스케줄러 트리거 (매일 04:00 AM)]
        │
        ▼
[1단계: Robots.txt 사전 파싱 (initRobotsTxtPolicy)]
   - https://www.wevity.com/robots.txt 다운로드 및 파싱
   - 'Disallow:' 경로를 파싱하여 Set<String>에 메모리 캐싱
        │
        ▼
[2단계: 수집 대상 URL 사전 검증 (isAllowedByRobotsTxt)]
   - 수집 URL이 Disallow 목록에 포함되는지 선제 검사
```

### 2. 핵심 백엔드 소스코드 발췌 (`WevityCrawlingService.java`)
```java
// WevityCrawlingService.java - Robots.txt 및 Fail-Safe 발췌
public boolean isAllowedByRobotsTxt(String targetUrl) {
    if (disallowedPaths.isEmpty()) return true;
    try {
        URI uri = new URI(targetUrl);
        String path = uri.getPath();
        for (String disallowed : disallowedPaths) {
            if (path.startsWith(disallowed)) {
                log.warn("[Robots.txt] 수집 제한 경로 감지되어 스킵합니다: {}", targetUrl);
                return false;
            }
        }
    } catch (Exception e) {
        log.error("[Robots.txt] URL 검증 오류: {}", e.getMessage());
    }
    return true;
}

// HTTP 상태 코드별 예외 분기 핸들링
catch (HttpStatusException hse) {
    int status = hse.getStatusCode();
    if (status == 403 || status == 401) {
        log.warn("[Crawling] 접근 거부(HTTP {}) 발생. 무리한 재시도를 중단하고 건너뜁니다: {}", status, detailUrl);
        continue;
    } else if (status == 429) {
        log.warn("[Crawling] 요청 제한(HTTP 429) 발생. 3초 대기 후 재시도합니다.");
        Thread.sleep(3000);
    } else if (status == 404) {
        log.warn("[Crawling] 존재하지 않는 페이지(HTTP 404): {}", detailUrl);
        continue;
    }
}
```

### 2. 졸업작품 최종 E2E 시연 시나리오 요약
1. **[사용자 A: 방장]** S4 공모전 상세페이지 진입 → 4대 AI 분석 리포트 확인 → [팀 빌딩 모집방 만들기] 클릭 → '백엔드 2명, 기획 1명' 동적 직무 TO 설정 후 모집방 개설.
2. **[사용자 B: 지원자]** S5 매칭 대시보드 진입 → AI 매칭 추천 점수(시간 일치도 + 기술 스택 가중치) 확인 → 사용자 A의 모집방에 [백엔드 지원하기] 클릭.
3. **[시스템 자동화]** 백엔드 트랜잭션에서 TO가 즉시 차감되며 네온 프로그레스 바 100% 도달 → 상태 머신이 `CLOSED(마감)` 상태로 자동 잠금 → 승인된 팀원들에게만 카카오톡 오픈채팅방 링크 버튼 활성화.
4. **[S8 회의록 AI 요약]** 카카오톡 대화 내용 복사 후 붙여넣기 → [AI 요약하기] 원클릭 실행 → 실시간 `gpt-4o-mini`가 정확한 안건, KST 일자, 장소, 역할을 카드 형태로 자동 추출하여 시연 마무리.
